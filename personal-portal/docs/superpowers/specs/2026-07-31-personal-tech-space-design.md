# 个人技术空间改版设计

- 日期：2026-07-31
- 状态：已确认
- 项目：Personal Portal
- 技术路线：在现有 React、TypeScript、Vite 项目上渐进演进
- 视觉方向：Gallery & Paper

## 1. 背景

当前项目已经具备 React 单页应用、基础国际化、动效组件、项目详情路由和
Netlify 部署链路，但主要内容仍是模板占位，视觉偏霓虹科幻控制台，也缺少适合
长期积累技术内容的结构。

本次改版把项目建设为一个持续生长的个人技术网站。它不是一份单独的“成长档案”
文档，而是同时服务以下用途的网站系统：

1. 记录技术备忘、可复用模块、UI、Demo 和项目实践。
2. 展示个人简历、职业经历和代表成果。
3. 为未来增加更多技术内容保留稳定的信息架构。

时间线不是首期重点。首期优先完成简历展示和技术藏宝阁。

## 2. 目标

### 2.1 产品目标

- 建立一个有个人辨识度的技术主页。
- 让访客快速理解站点作者的身份、能力和当前关注方向。
- 使用统一的“藏品”模型管理 Demo、UI、模块、技术备忘和项目。
- 使用仓库文件维护内容，提交 Git 后通过 Netlify 发布。
- 首期达到可公开分享的完成度。

### 2.2 首期成功标准

- 真实个人信息替换所有模板占位内容。
- 首页、藏宝阁、藏品详情和简历舱均可正常访问。
- 简历内容完整，重点经历支持分层展开。
- 上线 3–5 件有代表性的真实藏品。
- 中文内容完整；英文内容缺失时自动回退中文。
- 手机和桌面端均可正常浏览。
- Netlify 生产站点可通过现有域名访问。

### 2.3 首期不做

- 登录和自建管理后台。
- 第三方 CMS。
- 评论、点赞或用户账户。
- 完整技术成长时间线。
- 全文搜索和复杂筛选。
- 10 件以上的大规模内容整理。
- 自动生成独立 PDF 文件；首期提供可打印版式，由浏览器导出 PDF。

## 3. 技术路线

首期继续使用现有 React、TypeScript、Vite、React Router、Tailwind 和 i18next，
不迁移到 Astro 或 Next.js。

选择渐进演进的原因：

- 已有页面、动效、国际化和 Netlify 部署可以复用。
- 首期的主要风险是内容质量和产品结构，而不是框架能力。
- 文件驱动内容层可以与 UI 解耦；未来内容规模扩大后仍可迁移到 Astro。
- 避免在首期同时承担内容重写和框架迁移两类成本。

## 4. 信息架构

首页是完整网站主页，不再作为要求访客二选一的入口页。

| 路由 | 场景 | 职责 |
| --- | --- | --- |
| `/` | 暗色画廊 | 身份主张、当前关注、精选藏品、近期更新和简历入口 |
| `/vault` | 暗色画廊 | 浏览全部已发布藏品，并按类型进行基础筛选 |
| `/vault/:slug` | 混合 | 展示藏品正文、资源链接和可选的站内 Demo |
| `/resume` | 暖色阅读室 | 展示个人摘要、技能、经历、项目、联系信息和打印版式 |
| `*` | 跟随来源场景 | 友好 404，并提供返回首页或藏宝阁的入口 |

现有 `/projects/:id` 作为兼容路由保留一段时间：能够映射到新藏品时跳转到
`/vault/:slug`，无法映射时进入 404。

## 5. 视觉设计：Gallery & Paper

视觉系统由两个用途明确的场景组成，而不是允许用户随意切换的明暗主题。

### 5.1 Gallery Mode

用于首页、藏宝阁列表和 Demo 预览：

- 墨黑背景、暖白文字和单一冷蓝强调色。
- 大字号无衬线标题和宽松留白。
- 藏品封面承担主要视觉表达。
- 使用轻量淡入、位移和封面悬停反馈。
- 不再使用满屏霓虹描边、CRT 扫描线、持续粒子和自定义光标。

### 5.2 Paper Mode

用于技术正文、藏品说明和简历舱：

- 暖灰纸张背景、深色正文和同一冷蓝强调色。
- 标题可使用阅读型衬线字体，正文保持清晰克制。
- 强调编辑式排版、目录、引用、代码和长文阅读节奏。
- 打印时移除导航、背景效果和操作按钮。

### 5.3 两个场景的统一锚点

- 导航的位置、内容和交互一致。
- 使用同一套间距、栅格、圆角和动画时长。
- 只使用一个品牌强调色。
- 元数据统一使用等宽字体，正文不滥用等宽字体。
- 页面切换使用柔和背景过渡，不做戏剧化转场。

## 6. 页面设计

### 6.1 首页

首页保持短而有更新感，按以下顺序展示：

1. 个人身份主张和一句解释。
2. 当前技术关注方向。
3. 三件精选藏品。
4. 近期更新或技术备忘。
5. 代表成果和简历入口。
6. 联系方式与站点信息。

首页不复制完整简历，也不展示所有藏品。

### 6.2 藏宝阁

藏宝阁统一收录五类内容：

- `demo`：可交互实验。
- `ui`：视觉或交互界面作品。
- `module`：可复用功能模块。
- `note`：技术备忘或实践总结。
- `project`：完整项目或外部作品。

首期提供类型筛选和标签展示，不提供全文搜索。每张卡片至少显示封面、类型、
标题、摘要和更新时间。

### 6.3 藏品详情

所有藏品都支持图文说明，其他能力按内容成熟度渐进增强：

- 可选站内 Demo。
- 可选源码地址。
- 可选外部演示地址。
- 可选截图和相关藏品。

`demo`、`ui`、`module` 和 `project` 可以先使用暗色预览舞台，再进入暖色说明区。
`note` 直接使用暖色阅读室。

### 6.4 简历舱

简历舱默认是一份易扫描的在线简历，包含：

- 个人摘要。
- 核心技能。
- 工作经历。
- 项目经历。
- 教育或其他必要信息。
- 联系方式。

重点经历可以展开，使用“背景、行动、难点、结果”的结构补充上下文。打印版复用
同一份数据，不单独维护第二套简历内容。

## 7. 内容模型

### 7.1 建议目录

```text
src/
  content/
    resume/
      profile.ts
      experiences/
        <experience-slug>.mdx
    vault/
      <treasure-slug>/
        index.mdx
        assets/
  demos/
    registry.ts
    <demo-slug>/
      index.tsx
```

个人资料、技能和联系方式使用结构化 TypeScript 数据。经历详情和藏品正文使用
Markdown/MDX。每件藏品的资源与正文放在同一目录，便于整体移动、删除和迁移。

### 7.2 藏品元数据

每件藏品包含以下字段：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `slug` | 是 | 唯一地址标识 |
| `title` | 是 | 中文标题 |
| `summary` | 是 | 卡片和分享摘要 |
| `type` | 是 | `demo`、`ui`、`module`、`note` 或 `project` |
| `tags` | 是 | 技术和主题标签 |
| `createdAt` | 是 | 创建日期 |
| `updatedAt` | 是 | 最近更新日期 |
| `status` | 是 | `draft` 或 `published` |
| `featured` | 是 | 是否在首页精选 |
| `cover` | 是 | 列表和分享封面 |
| `demoKey` | 否 | 站内 Demo 注册标识 |
| `sourceUrl` | 否 | 源码地址 |
| `externalUrl` | 否 | 外部演示或项目地址 |

首期中文为必填内容。英文元数据或正文不存在时由内容加载层回退中文。

### 7.3 Demo 注册

可运行 Demo 不通过正文传入任意组件路径，而是在 `src/demos/registry.ts` 中显式
注册。藏品只引用 `demoKey`。这样可以保持依赖清晰、支持按需加载，也避免内容文件
执行未经控制的组件。

## 8. 组件边界

建议将页面拆为以下职责明确的单元：

- `SiteShell`：共享导航、页脚和场景切换。
- `HomePage`：组合首页各区块，不直接解析内容文件。
- `VaultPage`：处理类型筛选和藏品列表。
- `TreasureCard`：统一展示藏品摘要。
- `TreasureDetailPage`：根据藏品类型组合预览和正文。
- `DemoStage`：按需加载 Demo，并提供错误边界。
- `ResumePage`：组合简历摘要、技能和经历。
- `ExperienceDetail`：展示重点经历的分层内容。
- `contentLoader`：加载、校验、排序、筛选和语言回退。
- `demoRegistry`：维护 `demoKey` 到可加载组件的映射。

页面组件只消费标准化数据，不直接处理 Markdown 文件路径或语言回退。

## 9. 数据流

```text
Markdown/MDX + TypeScript 数据
          ↓
构建时内容加载与字段校验
          ↓
标准化 Resume / Treasure 数据
          ↓
首页查询精选与近期内容
藏宝阁查询已发布内容
详情页按 slug 查询单件藏品
          ↓
Vite 构建
          ↓
GitHub dev_1 → Netlify
```

只有 `published` 内容进入生产列表和详情路由。首页从同一份藏品数据中读取精选和
近期内容，不维护第二份首页配置。

## 10. 交互与响应式

- 常规动画控制在约 180–260ms。
- 悬停反馈只影响封面、标题或方向箭头。
- 支持键盘焦点和系统“减少动态效果”设置。
- 大图和 Demo 延迟加载。
- 桌面端使用宽松多列栅格，移动端改为单列。
- 导航在移动端保持简洁，不把所有筛选项塞入首屏。
- 页面内容变化后保持合理的滚动和焦点行为。

## 11. 异常处理

- 构建时校验必填字段、合法类型、日期和重复 `slug`。
- 校验失败时阻止构建，并输出具体内容文件和字段。
- 草稿不生成生产入口。
- 无效 `slug` 进入统一 404。
- 图片失败时显示稳定尺寸的占位状态。
- Demo 使用独立错误边界；Demo 崩溃不影响正文。
- 外部链接使用安全的新窗口属性。
- 英文缺失时回退中文。
- 可选区块没有数据时直接隐藏，不展示空容器。

## 12. 性能、无障碍与分享

- 首屏优先加载文字和精选封面。
- Demo 使用动态导入，不进入所有页面的首屏包。
- 图片提供明确尺寸，减少布局抖动。
- 颜色对比度、焦点样式和语义结构满足常规无障碍要求。
- 每个页面生成独立标题、摘要和分享封面信息。
- 保留 `public/_redirects`，确保 Netlify SPA 深层路由回退到 `index.html`。

## 13. 验证策略

遵循仓库约定，代码修改完成后先询问用户，再运行验证。建议顺序为：

1. `npm run build`，覆盖 TypeScript 和 Vite 构建。
2. `npm run lint`。
3. 手动检查首页、简历、藏宝阁、藏品详情、旧项目兼容路由和 404。
4. 检查手机与桌面布局、键盘导航、减少动效和打印简历。
5. 检查 Netlify 预览部署，再确认生产发布。

首期默认不新增自动化测试文件。若实施时内容加载、路由兼容或 Demo 隔离的风险明显
扩大，再说明风险并征得用户同意后补充测试。

## 15. 实施阶段

### 阶段一：网站框架与设计系统

- 建立 Gallery & Paper 的颜色、字体、间距和动效变量。
- 重建共享导航、页脚和页面框架。
- 完成新版首页静态结构。

### 阶段二：内容基础设施

- 接入 Markdown/MDX。
- 实现内容模型、加载、校验、语言回退和 Demo 注册表。
- 完成藏宝阁列表与藏品详情。
- 兼容旧项目详情地址。

### 阶段三：简历与真实内容

- 完成分层简历舱和打印样式。
- 替换个人信息、联系方式和现有占位项目。
- 准备 3–5 件代表性藏品。

### 阶段四：检查与发布

- 经用户确认后运行约定验证。
- 修复阻断问题。
- 推送 `dev_1`，检查 Netlify 构建和生产页面。

## 16. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 改版范围过大 | 首期不做后台、评论、时间线和全文搜索 |
| 明暗场景割裂 | 统一导航、栅格、强调色、间距和动画 |
| MDX 内容破坏构建 | 构建时校验并显式注册 Demo |
| 内容不足导致页面空洞 | 发布前准备 3–5 件真实藏品 |
| 双语维护成本过高 | 中文优先，英文缺失时回退中文 |
| Demo 影响页面稳定性 | 动态加载并使用独立错误边界 |

## 17. 验收标准

- 首页具有完整网站主页结构，并采用暗色画廊视觉。
- 简历舱位于二级页面，采用暖色阅读视觉。
- 藏宝阁能够展示和筛选五类藏品。
- 至少 3 件真实藏品可访问，其中允许同时存在可运行与图文类型。
- 所有模板姓名、联系方式和示例链接均已移除。
- 中文路径和内容完整；缺少英文时不会出现空白。
- 无效路由、资源失败和 Demo 崩溃均有可恢复状态。
- 移动端、键盘操作、减少动效和打印简历达到可用状态。
- Netlify 生产站点能够打开首页和深层路由。
