## 1. 项目使命

Personal Portal 是一个持续生长的个人技术网站，不是一份单独的“成长档案”文档。
它同时承担三种职责：

1. 沉淀技术备忘、可复用模块、UI、Demo 和项目实践。
2. 展示简历、职业经历、代表项目和工作方式。
3. 记录技术方向的变化，为未来求职、合作和个人表达提供可信材料。

当前优先级是：

1. 让访客快速理解作者是谁、擅长什么、正在关注什么。
2. 通过真实项目和可运行实验展示技术判断，而不是只罗列技能。
3. 保持内容系统易维护，使新项目可以持续进入藏宝阁。

完整成长时间线不是近期重点。

## 2. 产品结构

锁定的信息架构：

| 路由 | 角色 |
| --- | --- |
| `/` | 网站主页：身份主张、当前关注、精选藏品、最近更新和简历入口 |
| `/vault` | 技术藏宝阁：项目、Demo、UI、模块和技术备忘 |
| `/vault/:slug` | 藏品详情：预览、技术正文、证据和安全的外部资源 |
| `/resume` | 简历舱：个人摘要、技能、工作经历、项目和打印版式 |

首页不是完整简历，也不是要求访客二选一的入口页。简历舱和藏宝阁是二级页面。

## 3. 视觉与体验方向

长期视觉方向是 `Gallery & Paper`：

- Gallery：墨黑背景、暖白文字、冷蓝主强调色、克制暖色辅助、充足留白。
- Paper：暖灰纸张、深色正文、编辑式排版、清晰的长文阅读节奏。
- 封面承担视觉表达；页面不依赖满屏霓虹、扫描线、自定义光标或持续背景粒子。
- 动效服务于理解和反馈，尊重 `prefers-reduced-motion`。
- 手机与桌面端都必须可读，不以桌面截图代替响应式验收。
- “高级”来自比例、留白、字体层级、内容可信度和交互克制，不来自装饰堆叠。

现有设计规格：

- `docs/superpowers/specs/2026-07-31-personal-tech-space-design.md`

## 4. 内容系统

藏宝阁使用统一的文件驱动模型：

```text
src/content/vault/<slug>/
  meta.json
  index.mdx
public/covers/<slug>.svg
```

支持的类型：

- `project`：完整项目或外部作品。
- `demo`：可运行交互实验。
- `ui`：视觉或交互界面。
- `module`：可复用功能模块。
- `note`：技术备忘或实践总结。

首页精选是主动策展，不等于“最近创建的三项”。不得为了排序编造日期。

## 5. 公开内容真实性

所有公开表述必须满足：

- 能由源码、提交、设计文档、验证输出或用户明确说明支持。
- 区分“用户独立规划”“参与开发”“完全独立开发”三种不同归属。
- 区分“代码已实现”“构建已验证”“真实环境已部署运行”。
- 区分“免费额度内运行的设计约束”和“实际账单为零”。
- 不用未执行的测试、未完成能力或规划文档制造完成度。
- 不在公开案例中加入防御性的 AI 参与声明；需要说明协作方式时，由用户决定口径。
- 工作经历无法公开内部页面时，使用职责、问题、技术判断和可证明结果，不伪造截图。

当公开表述存在不确定性时，暂停并交由用户决定，不自行猜测。

## 6. 隐私与安全边界

- 不公开登录邮箱、密钥、令牌、服务账号、真实坐标或真实私密内容。
- Together Trace 只引导访客使用本地模式，不引导登录，不展示情侣真实数据。
- Together Trace 当前没有公开源码入口，因此 Personal Portal 不展示其 `sourceUrl`。
- 真实截图必须先确认没有私人信息；不确定时使用抽象封面或假数据。
- Netlify、Cloudflare、Firebase 和 GitHub 的账号操作不属于 Claude 的默认权限。

## 7. 工程原则

- 优先沿用 React、TypeScript、Vite、React Router、MDX 和现有内容加载模型。
- 不为近期需求迁移框架，不引入 CMS、后台、登录或数据库。
- 遵循现有文件边界；新抽象必须解决当前可证明的问题。
- 修复根因，不用错误边界、禁用规则或静默降级掩盖代码问题。
- React 中需要 DOM 访问时优先使用 ref；异步 Effect 要防止过期响应。
- 公共组件、可复用方法和自定义 Hook 按仓库规范编写 JSDoc。
- React/Tailwind 使用标准类，不使用可由内置类表达的任意值语法。
- 不默认新增测试；允许自主运行和维护已有测试。需要创建新测试时先请求用户确认。

## 9. Claude 与 Codex 的协作模型

### Claude

Claude 是连续执行者，负责：

- 在阶段 1–4 内自主分析、实现和验证，并在子阶段完成后继续推进。
- 保持小而完整的本地提交。
- 维护 `docs/PROJECT_STATUS.md` 和追加式时间线，使新会话可以直接继续。
- 用证据记录完成度，不把推断写成事实。
- 只有触发暂停条件时才请求用户或 Codex。

### Codex

Codex 是长期验收者，负责：

- 在阶段门槛检查产品方向、代码质量、公开表述、隐私和验证证据。
- 对架构变化、重大技术债和发布候选状态做把关。
- 不再逐 commit 分发普通实现任务，也不充当日常传话人。

### 用户

用户负责：

- 决定产品方向、公开口径和个人信息。
- 授权 push、部署、外部账号操作和其他不可逆动作。
- 在重大方向存在多个合理选择时作最终决定。

## 10. 阶段路线

### 阶段 1：工程基线转绿

目标：

- 清零当前 7 个 lint error 和 1 个 warning。
- 保持 Build 通过。
- 保持 Particle Field、Typewriter、首页、藏宝阁、Together Trace 和简历行为正常。
- 不新增产品功能，不进行无关视觉重设计。

Claude 可以在阶段内自行拆分提交、运行已有测试和浏览器检查。达到验收标准后记录
证据并直接进入阶段 2。

### 阶段 2：当前工作证据与脱敏草稿

目标：

- 在仓库外收集当前工作的事实、职责、技术判断和可证明结果。
- 将可公开内容转化为不包含雇主机密、内网细节和个人隐私的候选文案。
- 明确哪些内容有证据、哪些内容需要用户补充或确认。
- 用户只需在形成一版完整脱敏草稿后确认公开口径，不逐条参与整理。

原始材料不得进入受版本控制的公开仓库。用户确认前，不把候选文案写入公开页面。

### 阶段 3：简历与代表内容整合

目标：

- 把用户确认过的当前工作内容整合到简历舱和合适的项目案例。
- 把 Together Trace、Personal Portal、supET 打磨成可信、易扫描的代表案例。
- 补齐安全封面、必要截图、技术判断和结果证据。
- 固化新增藏宝阁内容的模板和检查清单，保持文件驱动。

### 阶段 4：全站质量优化

目标：

- 系统检查并优化手机与桌面响应式、交互一致性、可访问性和减少动态效果。
- 优化性能、SEO、深层路由、错误状态和简历打印版式。
- 保持视觉方向和内容真实性，不进行无目标的重新设计。
- 形成可重复的全站验收结果。

### 阶段 5：发布候选

目标：

- 汇总阶段 1–4 的验证、已知风险、公开内容确认和部署前检查。
- 由 Codex 做长期验收与方向把关。
- 保持本地 commit；未经用户明确授权不部署。

## 11. 阶段门槛

Claude 只在以下时点暂停并交给用户或 Codex：

- 需要修改本章程的锁定方向。
- 发现隐私、真实性或架构风险。
- 当前工作脱敏草稿已经完整，需要用户确认公开口径。
- 同一问题连续三次修复失败。
- 阶段 4 已完成，准备形成阶段 5 发布候选。
- 准备部署或执行其他外部写操作。

阶段 1–4 的普通代码审查、局部重构、内容整理和验证由 Claude 自行完成；完成一个
子阶段后更新状态板和时间线，直接进入下一子阶段。

## 12. 完成定义

一个长期阶段只有同时满足以下条件才算完成：

- 目标范围已全部实现，没有隐藏的跳过项。
- 实际运行的验证命令和退出码被记录。
- 未通过的检查被明确标为失败，而不是包装成通过。
- 浏览器相关功能经过刷新后的页面验证。
- 工作树除已知 `../.DS_Store` 外干净。
- 本地 commit 使用正确身份，未 push、未部署。
- `docs/PROJECT_STATUS.md` 已更新为可由新会话直接继续或验收的状态。
- `docs/timeline/` 已追加本批次事件，包含验证、风险、next owner 和第一动作。
