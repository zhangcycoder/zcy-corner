# 马尔可夫文本生成器

这个 demo 里没有大模型,也没有预录的输出。你看到的每一段文字,都是浏览器现场在选中的语料上算出一条**字符级马尔可夫链**,再一个字一个字采样出来的。它常常写出局部读得通、整体不知所云的句子——这不是 bug,而是马尔可夫链的本质:它只有局部统计,没有任何理解。

## 马尔可夫链是什么

马尔可夫链的核心假设只有一句话:**下一个状态只取决于当前的有限历史,和更早的一切无关。**

放到文本里,「状态」就是最近的几个字。这个 demo 做的是最朴素的版本:

- 把语料从头扫到尾,在每个位置取出**前 n 个字**作为前缀,记下**紧跟其后的那个字**。
- 对同一个前缀,统计它后面各个字分别出现了多少次,得到一张频次表。
- 生成时,从一个句首前缀出发,查表、采样出下一个字,再把窗口向后滑一格,如此重复,直到长度上限、或走进某个没有后继的「死胡同」自然停下。

整条链就是这样一张「前缀 → 下一个字的频次」的大表。demo 里那行 `阶数 n · 语料 N 字 · M 个状态`,`M` 就是这张表里不同前缀的数量,是从真实模型里数出来的,不是编的。

之所以做成**字符级**而不是词级,是因为中文没有天然的空格分词。按字统计,不需要任何分词库就能直接在中文上跑起来——代价是它对「词」毫无概念,只认识一个字接一个字的接续。

## 阶数 n 改变了什么

阶数就是前缀的长度,也就是「往回看几个字」。

- **n 小(1~2)**:前缀短,同一个前缀在语料里跟着五花八门的后继,分叉极多。生成的文本非常自由,却也非常破碎,经常在半句话中间拐向完全无关的地方。
- **n 大(3~4)**:前缀长,能匹配上的接续越来越少,选择被大幅收窄。文本变得通顺,但因为长前缀在语料里往往只出现过一两次,模型很容易只剩一条路可走,于是开始**大段照抄原文**。

所以阶数是一个滑块的两端:一端是发散到失控,另一端是收敛到复读。中间的 2~3 阶,通常是「像话」和「有点意思」之间最微妙的地带。

## 温度改变了什么

有了频次表,怎么从里面挑下一个字?最直接的办法是按频次比例来抽——出现 8 次的字被选中的概率,就是出现 2 次的字的四倍。**温度**是在这个基础上给分布做的一次重塑:

- 把每个候选的权重取成 `次数^(1/T)`。
- **低温(T→0)**:指数变大,高频的字被进一步放大,低频的字被压没,分布变得尖锐——输出更保守、更贴近语料里最常见的说法,趋近于「每次都选最高频」。
- **高温(T 越大)**:指数趋近 0,所有候选的权重被拉平,分布趋于均匀——输出更大胆、更容易蹦出意想不到的字,也更容易语无伦次。
- `T=1` 时权重就是原始频次,等价于最朴素的**最大似然采样**。

温度不改变模型学到的任何统计,它只调节「有多听话」。同一条链,低温像谨慎的复述者,高温像喝多了的即兴表演。

## 为什么局部通顺、整体离谱

这是理解马尔可夫链最重要的一点。

它每走一步,眼里只有当前前缀这几个字,压根不知道这句话在讲什么、上一句说了什么、整段要往哪去。**相邻的字之间因为统计接续而顺滑,跨越几个字之外就彻底失忆。**于是你会看到:词与词的衔接是自然的,可是主语走着走着就丢了,一句话的开头和结尾对不上,通篇没有一个贯穿的意思。

这恰恰划清了「统计接续」和「理解」的界线。马尔可夫链把「像人话」这件事拆穿了——**局部的流畅可以完全由频次堆出来,而连贯的意义不能。**它没有意图、没有记忆、没有对世界的模型,它拥有的只是一张频次表。

## 诚实说明

这个 demo 里跑的是货真价实的马尔可夫链:构建频次表、按温度采样、滑动窗口生成,全部在 `src/demos/markov/index.tsx` 里用纯 JavaScript 手写,**不联网、不加载任何 NLP 或马尔可夫库,也没有任何预先写死的输出**。模型就建立在页面上那两段语料之上——两段短文都是本人手写,你换语料、调阶数、拨温度,统计和采样都会跟着实时变化。首屏为了稳定展示,先用「每步选最高频」的确定性走法给一段预览;一旦你按下「生成」或调动任何参数,后续就是真正的随机采样,每次结果都不一样。

它是一个玩具,也正因为小,才能把「生成」这件事讲清楚:没有魔法,只有一张数出来的表,和一次次按概率的掷骰子。
